## OSI参照モデル
### 概要
- OSI参照モデルとは、ネットワーク通信に必要な機能を7つの階層に分けて整理したモデルである
- 複雑なネットワーク通信を役割ごとに分けることで、通信の仕組みを理解しやすくなり、障害が発生した際にも原因を特定しやすくなる
- 通信のどの部分で問題が発生しているのかを把握できる
- 通信に関係する機器やプロトコルを整理できる
- ネットワークの仕組みを階層ごとに理解できる

### OSI参照モデルとは
OSI参照モデルは、ネットワーク通信の機能を7つの層に分けて考えるためのモデルである
各層はそれぞれ異なる役割を持ち、連携することでデータの送受信を実現する

### OSI参照モデルの7階層
| 層 | 名称 | 主な役割 |
| ------ | ------ | ------ |
| 第7層 | アプリケーション層 | アプリケーションが利用するネットワークサービス |
| 第6層 | プレゼンテーション層 | データ形式の変換、暗号化、圧縮など |
| 第5層 | セッション層 | 通信セッションの確立・維持・終了 |
| 第4層 | トランスポート層 | データの分割、端末間の通信、通信の信頼性など |
| 第3層 | ネットワーク層 | IPアドレスによる論理的な宛先指定と経路選択 |
| 第2層 | データリンク層 | 同じリンク内でのフレームの送受信 |
| 第1層 | 物理層 | 電気信号・光信号・電波などによるデータ伝送 |

## 各層の役割
### 第7層：アプリケーション層
- アプリケーションがネットワークサービスを利用するための機能を提供する層
#### 代表的なプロトコル
- HTTP / HTTPS：Web通信
- DNS：ドメイン名とIPアドレスの対応付け
- SMTP：電子メールの送信・転送
- FTP：ファイル転送

### 第6層：プレゼンテーション層
- アプリケーション間で扱うデータの表現形式を整える役割を持つ
### 主な役割
- データ形式の変換
- 文字コードなどの表現形式の調整
- 暗号化・復号
- 圧縮・展開

### 第5層：セッション層
- 通信する機器やアプリケーション間のセッション（通信のやり取り）を管理する層
#### 主な役割
- セッションの確立
- セッションの維持・管理
- セッションの終了

### 第4層：トランスポート層
- アプリケーション間のデータ転送を制御する層。通信方式に応じて、信頼性や転送効率などを調整する。
#### 代表的なプロトコル
- TCP：接続を確立し、データの順序や再送などを制御して信頼性の高い通信を実現する
- UDP：接続確立などの手順を省き、少ない制御でデータを送信する
- ポート番号を利用して、どのアプリケーション宛てのデータなのかを識別する

### 第3層：ネットワーク層
- 異なるネットワーク間でデータを届けるための経路選択や論理アドレスによる宛先指定を担当する層
#### 主な役割
- IPアドレスによる宛先指定
- ルーティング（通信経路の選択）
- 異なるネットワーク間でのパケット転送
#### 代表的なプロトコル
- IPv4
- IPv6
- ICMP
#### 代表的な機器
- ルータ
- レイヤー3スイッチ

### 第2層：データリンク層
- 同じネットワークリンク内で、フレームを送受信するための機能を担当する層
#### 主な役割
- フレームの作成と送受信
- MACアドレスによる識別
- 通信媒体へのアクセス制御
- フレームのエラー検出
#### 代表的な技術・プロトコル
- Ethernet
- Wi-Fi
#### 代表的な機器
- レイヤー2スイッチ
- ブリッジ

### 第1層：物理層
- データを電気信号・光信号・電波などに変換し、物理的な伝送媒体を通じて送受信する層
#### 主な役割
- 信号の送受信
- ケーブルやコネクタなどの物理的な接続
- 信号の伝送方式や速度などの規定
#### 関連するもの
- LANケーブル
- 光ファイバー
- 無線電波
- リピーターやハブ

### データの送受信とカプセル化
- 送信側では、データは上位層から下位層へ渡される過程で、各層の情報が付加される。この処理をカプセル化という
- 受信側では、下位層から上位層へ進む過程で各層の情報が取り除かれ、元のデータが取り出される。これを非カプセル化という
#### 代表的なデータの呼び方
| 層 | データの呼び方(代表例) |
| ------ | ------ |
| 第4層 | セグメント（TCP）、データグラム（UDP） |
| 第3層 | パケット |
| 第2層 | フレーム |
| 第1層 | ビット |

### OSI参照モデルをトラブルシューティングに活用する
- 通信できない場合、OSI参照モデルに沿って下位層から順に確認すると、問題の切り分けに役立つ
#### 例
- 第1層：ケーブルが正しく接続されているか、リンクランプが点灯しているか
- 第2層：スイッチの接続やVLANの設定が正しいか
- 第3層：IPアドレス、サブネットマスク、デフォルトゲートウェイ、経路が正しいか
- 第4層：必要なポートが通信可能か、TCP接続が確立できるか
- 第7層：DNSやWebサービスなど、アプリケーションの設定に問題がないか

### 学び
- OSI参照モデルは、ネットワーク通信を7つの階層に分けて整理するためのモデルである
- 各層にはそれぞれ異なる役割があり、連携して通信を実現する
- 第4層ではTCPやUDP、第3層ではIP、第2層ではMACアドレスやフレームが重要になる
- データは送信時にカプセル化され、受信時に非カプセル化される
- OSI参照モデルを利用すると、ネットワーク障害の原因を層ごとに切り分けやすくなる
