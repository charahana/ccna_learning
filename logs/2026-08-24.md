## Telnetのセキュリティ上の問題
### 概要
- Telnetはネットワーク経由でサーバやネットワーク機器をリモート操作するためのプロトコルである
- Telnet接続ではログイン後、CLI(コマンドラインインターフェース)を使用して、許可された操作を実行できる
- Telnetは通信内容を暗号化しないため、セキュリティ上の問題がある
- 現在はTelnetよりも安全なSSHを使用することが一般的である

### Telnetのセキュリティ問題
- Telnetではユーザー名やパスワードを含む通信データが平文で送信される
- 通信内容が暗号化されていないため、ネットワーク上で通信を傍受されると認証情報やコマンドなどを読み取られる可能性がある
- ログイン後はユーザーに許可された範囲でサーバやネットワーク機器を操作できるため、認証情報が漏れると不正操作に繋がる危険性がある

### SSH
- SSHはTelnetに代わる安全なリモートアクセスのためのプロトコルである
- 通信内容を暗号化することでリモートアクセス時のデータを保護する
- Telnetと同様にリモートからCLIを操作するために利用できる
- 認証機能も備えており、安全なリモート管理に利用される
- Cisco機器のリモート管理でもTelnetではなくSSHを使用することが推奨される

### TelnetとSSHの違い
| 項目 | Telnet | SSH |
| ------ | ------ | ------ |
| 用途 | リモートアクセス | リモートアクセス |
| 通信の暗号化 | なし | あり |
| データ | 平文 | 暗号化 |
| セキュリティ | 低い | 高い |
| 標準ポート | TCP23 | TCP22 |

### 学び
- Telnetはリモートアクセス用のプロトコルだが通信を暗号化しない
- Telnetではログイン情報やセッション中のデータが平文で送信される
- Telnet = TCP23、SSH = TCP22という対応関係を覚える
- SSHは通信を暗号化できるため、安全なリモート管理に利用される
- ネットワーク機器のリモート管理では、TelnetよりSSHを使用することが重要であることを理解した
