## ネットワークセキュリティ/ファイアウォール/ACL
### 概要
- ネットワークセキュリティとはネットワークを経由する不正アクセスや攻撃、情報漏洩などからシステムやデータを守るための対策のことである
- 外部からの攻撃だけでなく、内部ネットワークからの不正な通信や情報漏洩も対策対象となる
- ネットワークを安全に利用するためには、すべての通信を許可するのではなく、必要な通信だけを許可するという考え方が重要になる
### ネットワークセキュリティとは
ネットワーク上の脅威から、コンピュータやサーバ、ネットワーク機器、情報資産などを保護すること
#### 代表的な脅威
| 脅威 | 内容 |
| ------ | ------ |
| 不正アクセス | 許可されていないユーザがシステムへ侵入すること |
| マルウェア | ウイルスやランサムウェアなど、悪意のあるソフトウェア |
| DoS/DDoS攻撃 | 大量の通信などによってサービスを利用できない状態にする攻撃 |
| 通信の盗聴 | ネットワーク上の通信内容を不正に取得すること |
| 内部からの情報漏洩 | 内部関係者などによって機密情報が外部へ流出すること | 

#### セキュリティ対策の基本的な考え方
- 必要な通信だけを許可する
- 不要なポートやサービスを停止する
- アクセス権限を適切に設定する
- 通信を監視し、不審な動きを検知する
- OSやソフトウェアを最新の状態に保つ

### ファイアウォール（Firewall）
- ファイアウォールとは、ネットワーク間の通信を監視/制御し、設定されたルールに従って通信を許可または拒否する仕組みのことである
- 外部ネットワークと内部ネットワークの間などに設置し、不正なアクセスや不要な通信を防ぐ
#### 主な仕組み
- 送信元IPアドレス
- 宛先IPアドレス
- プロトコル（TCP/UDPなど）
- ポート番号
#### 例
- HTTP（80番）やHTTPS（443番）の通信を許可する
- SSH（22番）の通信は管理者のIPアドレスからのみ許可する
- 不要な通信や許可されていない通信を拒否する

### IDS/IPS
IDSとIPSは、不正な通信やサイバー攻撃を検知/防御するための仕組みのことである
#### IDS（侵入検知システム）
- 不審な通信や攻撃を検知する
- 検知した内容を管理者へ通知する
- 基本的には検知/通知が役割であり、通信を自動的に遮断するものではない
#### IPS（侵入防止システム）
- 不審な通信や攻撃を検知する
- 不正な通信を遮断する
- 攻撃による被害を防ぐために利用される
#### IDSとIPSの違い
- IDS：不正な通信を検知して知らせる
- IPS：不正な通信を検知して遮断する

### WAF（Web Application Firewall）
- WAFとは、Webアプリケーションを狙った攻撃から保護する仕組みのことである
- 一般的なファイアウォールがIPアドレスやポート番号などを基に通信を制御するのに対し、WAFはHTTP/HTTPSの通信内容を検査し、Webアプリケーションへの攻撃を防ぐ
#### 代表的な攻撃
- SQLインジェクション：不正なSQL文を入力し、データベースを不正に操作しようとする攻撃
- クロスサイトスクリプティング（XSS）：Webページに悪意のあるスクリプトを埋め込み、利用者のブラウザ上で実行させようとする攻撃。
#### ファイアウォールとWAFの違い
| 比較項目 | ファイアウォール | WAF |
| ------ | ------ | ------ |
| 主な役割 | ネットワーク通信を制御 | Webアプリケーションを保護 |
| 主な検査対象 | IPアドレス/ポート番号/プロトコルなど | HTTP/HTTPSの通信内容 |
| 防御対象 | 不要な通信や不正なアクセス | SQLインジェクション/XSSなど |

### ACL（Access Control List）
- ACLとは、通信条件をルールとして定義し、特定の通信を許可または拒否する仕組みのことである
- ルータやレイヤ3スイッチなどで利用され、送信元や宛先のIPアドレス、プロトコル、ポート番号などを基に通信を制御する

### ACLの主な種類
#### 標準ACL（Standard ACL）
- 送信元IPアドレスのみを確認する
- 宛先IPアドレスやポート番号は指定できない
- 比較的シンプルな通信制御に利用される
#### 拡張ACL（Extended ACL）
- 標準ACLよりも細かい通信制御ができる
- TCP/UDP/ICMPなどのプロトコルを指定できる
- HTTPやSSHなど、特定のサービスへの通信を制御できる
#### 名前付きACL（Named ACL）
- ACLの目的や用途が分かりやすくなる
- 標準ACLと拡張ACLの両方で利用できる
- 名前を付けることで管理しやすくなる
#### VTYへのACL
- VTY（Virtual Teletype）とは、TelnetやSSHなどを利用してルータやスイッチへリモート接続するための仮想端末回線のことである
- VTYにACLを適用することで、リモート管理接続を許可する送信元IPアドレスを制限できる

### ACLの重要ポイント
#### 暗黙の拒否（Implicit Deny）
- ACLでは、設定した許可/拒否ルールの後に、明示的に記述されていなくても、すべての通信を拒否するルールが存在する
- そのため、許可したい通信をACLに設定しないと、その通信も拒否される可能性がある
#### ACLの適用方向
- Inbound（インバウンド）：インターフェースに入ってくる通信にACLを適用する
- Outbound（アウトバウンド）：インターフェースから出ていく通信にACLを適用する。
- ACLはインターフェースに適用することで、指定した方向の通信を制御する

### 学び
- ネットワークセキュリティは、不正アクセスや攻撃、情報漏洩などからシステムやデータを守るための対策だと理解した
- ファイアウォールはIPアドレスやポート番号などを基に通信を制御することを理解した
- IDSは不正な通信を検知して通知し、IPSは検知した通信を遮断することを理解した
- WAFはHTTP/HTTPSの通信内容を検査し、Webアプリケーションへの攻撃を防ぐことを理解した
- ACLは通信条件を設定し、特定の通信を許可/拒否することを理解した
- 標準ACLは送信元IPアドレスを基に制御し、拡張ACLは宛先IPアドレスやポート番号なども基に制御することを理解した
- ACLには暗黙の拒否があるため、許可したい通信を適切に設定する必要があることを学んだ
